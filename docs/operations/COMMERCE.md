# 주문·결제 자동 처리

현재 결제는 토스 테스트 환경입니다. 공개 클라이언트 키는 웹 빌드 인자이고 서버 시크릿 키는 API 환경 파일에만 둡니다. GitHub development environment의 Secrets와 기존 CD 설정을 사용하며 저장소에 키를 넣지 않습니다.

## 화면 흐름

회원은 `/checkout`에서 배송 정보를 입력하고 주문을 접수한 다음 `/payments/{orderId}`에서 서버 확정 금액으로 결제합니다. 같은 입력의 통신 실패 재시도는 동일 Idempotency-Key를 사용합니다. 배송 정보 원문은 재시도용 브라우저 저장소에 기록하지 않습니다.

`/mypage`의 주문 내역에서 결제 대기·결제 완료·준비·배송·완료·취소 상태와 운송장을 확인합니다. 미결제 주문은 취소할 수 있고, 결제 완료/준비 상태는 PG 전액 환불 결과를 확인한 후 취소됩니다. 환불 응답이 불명확하면 취소 완료라고 표시하지 않습니다. 배송 이후 직접 취소는 차단됩니다.

관리자는 `/admin/orders/{id}`에서 결제 완료 주문만 준비 처리하고 택배사·운송장과 사유를 입력하여 출고합니다. 상태 변경은 서버 행 잠금과 이전 상태 비교로 직렬화하며 처리 이력을 보존합니다. 결제 완료를 관리자가 임의 지정할 수 없습니다. `/admin/payments`에서 미확정 결제·환불 및 금액 불일치 등 검토 내역을 확인합니다.

## 타이머

CD가 아래 명령으로 사용자 systemd timer를 설치·갱신합니다.

```sh
python3 ops/commerce.py install
python3 ops/commerce.py status
systemctl --user status aura-commerce.service --no-pager
journalctl --user -u aura-commerce.service -n 30 --no-pager
```

`aura-commerce.timer`는 이전 실행 종료 후 60초마다 단일 oneshot을 실행합니다. 각 실행은 API 컨테이너 1개에서 다음 순서로 최대 100건씩 처리합니다.

1. 2분 이상 결과가 불명확한 결제의 PG 결과 재확인.
2. 2분 이상 결과가 불명확한 환불의 PG 결과 재확인.
3. `AURA_UNPAID_ORDER_TTL_MINUTES`(기본 10분)가 지난 미결제 주문 취소와 재고·쿠폰 복구.

PG 재확인은 원래 식별자로 처리합니다. 알 수 없는 결과나 금액 불일치를 성공으로 변경하지 않으며, 결제 확인 중인 주문은 미결제 만료에서 제외합니다. 타이머 실행 제한은 240초이고 실패하면 다음 실행에서 다시 확인합니다. 배치 제한을 초과하는 대규모 처리량은 주기/배치 조정이 필요합니다.

실행할 때마다 `AURA_DATABASE_URL_FILE`의 현재 값을 새로 읽어 DB 비밀번호 회전과 승격 후 새 주 DB를 따릅니다. URL·비밀번호·배송지·PG 키를 journal에 출력하지 않습니다. 서비스가 없는 단일 API 환경도 같은 수동 실행을 사용할 수 있습니다.

```sh
python3 ops/commerce.py run
```

## DB 변경

0011은 상품 문의 테이블과 관리자 답변 감사 기록을 추가합니다. 0012는 기존 주문에 빈 기본값으로 연락처·배송 요청사항·택배사·운송장을 추가합니다. 운영 데이터는 비우지 않습니다. 배포 전에 기존 백업 단계를 수행하고 Alembic head 적용 후 API·웹을 갱신합니다.

관리자 답변 감사 기록에는 본문 대신 변경 버전만 보관합니다. 0011을 내릴 때 답변 감사 기록을 잃지 않도록 감사 로그의 허용 값 확장은 유지됩니다. 운영 롤백에서는 저장된 문의/배송 정보를 삭제하는 downgrade 대신 이전 앱 이미지로 복귀하고 DB는 유지합니다.
