# 시연 데이터

`ops/demo.py`는 기존 카탈로그와 운영자 계정을 사용해 가상 데이터를 추가합니다. 모든 이메일은 `example.invalid` 계열이고 이름·주소·연락처는 시연용 예시입니다. 관리자 계정을 추가하거나 운영 비밀번호를 바꾸지 않습니다.

| 데이터               |                              추가 수량 |
| -------------------- | -------------------------------------: |
| 체험 회원            |                                     24 |
| 회원별 무료배송 쿠폰 |                                     24 |
| 조향 기록            |                                     96 |
| 주문                 |                    72 (6개 상태 각 12) |
| 결제 예시            |                                     72 |
| 환불 예시            |                                     14 |
| 상품 문의            | 상품당 4 (기본 카탈로그 30개 기준 120) |
| 입점 문의            |              30 (접수·검토·완료 각 10) |

주문은 단품·여러 상품·커스텀 향, 수량·가격·배송비, 처리 이력과 운송장 예시를 포함합니다. 문의는 공개/비공개, 답변 완료/대기 상태를 포함합니다. 운영 대시보드의 주문 집계에는 시연 주문도 포함되며 실제 매출과 구분해서 봐야 합니다.

## 실행

기능 배포와 0013 마이그레이션 후 운영 체크아웃에서 실행합니다. 먼저 건수를 확인하고, 실행할 때 체험 회원용 비밀번호를 입력합니다. 비밀번호는 저장소·명령 인자·로그에 넣지 않습니다.

```sh
python3 ops/demo.py
python3 ops/demo.py --execute
```

자동화는 `AURA_DEMO_PASSWORD` 환경 변수 또는 `--password-stdin`을 사용합니다. 관리형 DB에서는 실행 전에 기존 백업 스크립트를 호출합니다. 실제 데이터 적재는 하나의 트랜잭션이고, 같은 생성기를 다시 실행해도 결정적 ID로 중복 생성을 막으며 기존 행과 체험 회원 비밀번호를 덮어쓰지 않습니다. CD는 시연 적재를 자동 실행하지 않습니다.

체험 회원 이메일은 `demo@aura.example.invalid`입니다. 이 계정으로 마이페이지의 저장한 향·구매 예시·주문 상태·내 문의·쿠폰을 보여줄 수 있습니다. 나머지 23개 회원은 목록 구성용으로 생성되며 로그인 비밀번호를 발급하지 않습니다.

## 시연 주문 분리

`orders.is_demo=true`, 결제 공급자 `demo`로 명시합니다. 기존 주문은 false가 기본값입니다. 고객 결제 승인·취소/환불, 관리자 배송 변경은 시연 주문을 409로 거절하며, 미결제 만료·결제/환불 자동 재확인에서도 제외합니다. 재고나 쿠폰을 예약하지 않으므로 실제 주문 상태를 흉내 내며 재고를 바꾸는 일이 없어야 합니다. 주문·결제 확인 화면에 시연 표식을 표시합니다. DB도 시연 주문의 UPDATE를 차단해 이전 앱 이미지로 복귀했을 때 가상 주문 만료로 실제 재고가 증가하지 않도록 보호합니다.

실제 주문 접수·토스 테스트 결제·환불 동작은 새 주문으로 보여줍니다. 시연 기록에 연결된 PG 키·운송장은 실제 거래·배송 식별자가 아닙니다.
