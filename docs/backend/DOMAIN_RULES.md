# AURA 도메인 규칙

> **상태:** 초안 · 팀 검토 전 · Linear CRA-11 (상위 CRA-5)
> **기준:** [백엔드 ERD](ERD.md), [FastAPI BFF 계약](../FASTAPI_BFF.md)(#24 로컬 장바구니 반영), Mock API(`apps/web/mock-server`)
> **코드:** `apps/api/aura_api/domain/<영역>.py` · **테스트:** `apps/api/tests/domain/`

## 1. 이 문서의 역할

ERD는 **무엇을 저장하는가**를, 도메인 규칙은 **그 데이터로 무엇을 할 수 있고 없는가**를 정한다. 지금은 이 규칙들이 브라우저와 Mock API에만 있어서 조작할 수 있다. 백엔드에서는 도메인 계층이 최종 판단한다.

| 규칙의 종류                                | 지키는 곳                                     | 예                                    |
| ------------------------------------------ | --------------------------------------------- | ------------------------------------- |
| 한 칸·한 줄만 보면 되는 규칙               | DB 제약 (ERD)                                 | 재고 ≥ 0, 이메일 중복 금지, 수량 1~15 |
| 여러 값을 더하거나 비교·계산해야 하는 규칙 | **도메인 계층** (이 문서)                     | 향료 합계 1~20, Gift Set 3개, 배송비  |
| DB를 조회해야 판단할 수 있는 규칙          | 애플리케이션 계층 + DB 제약을 최종 방어선으로 | 이메일 중복, 레시피 소유권, 실제 재고 |

도메인 코드는 FastAPI·SQLAlchemy·DB를 모르는 **순수 Python**이다. 입력을 받아 규칙대로 판단하고, 어기면 `DomainError`를 던진다.

## 2. 오류 형식

`aura_api/domain/errors.py`

| 클래스         | `kind`         | 표현 계층에서 매핑할 HTTP 상태 |
| -------------- | -------------- | ------------------------------ |
| `InvalidInput` | `invalid`      | 400                            |
| `Unauthorized` | `unauthorized` | 401                            |
| `NotFound`     | `not_found`    | 404                            |
| `Conflict`     | `conflict`     | 409                            |

모든 오류는 `code`(기계용)와 `message`(화면에 띄울 한국어 문장)를 가진다. 메시지는 Mock API·화면 문구와 같게 맞췄다. Mock은 규칙 위반을 400으로 돌려주므로 대부분 `InvalidInput`이다.

## 3. 회원 · 인증 (`identity/domain.py`)

> **인증은 JWT 방식이다.** 서버에 로그인 상태를 저장하는 세션 테이블은 두지 않는다. BFF 계약의 쿠키 이름(`API_SESSION_COOKIE`)과 응답 DTO 이름(`Session`)에 "session"이 들어갈 뿐, 그 쿠키 값은 서버가 서명한 **JWT**(회원 ID·비회원 ID·토큰 번호 `jti`·만료 시각)다. 요청마다 서명과 만료를 확인하고, 로그아웃한 토큰은 `revoked_tokens`에 기록해 거절한다.

| ID    | 규칙                                                                                                                            | 위반 코드 → 메시지                                               |
| ----- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| ID-01 | 이름은 공백 제외 1자 이상, 100자 이하. 앞뒤 공백 제거                                                                           | `NAME_INVALID` → 이름을 입력해 주세요.                           |
| ID-02 | 이메일은 254자 이하, 앞뒤 공백 제거 후 **소문자로 정규화**, `^\S+@\S+\.\S+$` 형식                                               | `EMAIL_INVALID` / `MEMBER_INVALID` → 회원 정보를 확인해 주세요.  |
| ID-03 | 비밀번호는 8자 이상 256자 이하                                                                                                  | `PASSWORD_INVALID` / `MEMBER_INVALID`                            |
| ID-04 | 마케팅 동의는 `true`일 때만 동의 (그 외 값은 미동의)                                                                            | —                                                                |
| ID-05 | 로그인 시 이메일은 같은 방식으로 정규화, 비밀번호는 비어 있으면 안 됨                                                           | `PASSWORD_REQUIRED` → 비밀번호를 입력해 주세요.                  |
| ID-06 | 요청의 주인(`RequestOwner`)은 회원이면 `member:{userId}`, 비회원이면 `guest:{guestId}`. `guestId`는 로그인·로그아웃 후에도 유지 | —                                                                |
| ID-07 | `X-Session-Owner`가 실제 주인과 다르면 거절 (계정이 바뀐 사이 시작된 요청). 소유권 판단은 이 헤더가 아니라 토큰으로             | `OWNER_CHANGED` (409) → 계정이 변경되었어요. 다시 시도해 주세요. |
| ID-08 | 배송비 쿠폰은 `AVAILABLE`일 때만 사용할 수 있고, 사용하면 `USED`. 주문 취소 시 복원 가능                                        | `COUPON_UNAVAILABLE` → 사용할 수 없는 쿠폰이에요.                |
| ID-09 | `Member.coupon`(쿠폰 보유)은 저장하지 않고 "사용 가능한 쿠폰이 있는가"로 계산                                                   | —                                                                |

애플리케이션 계층에서 처리: 이메일 중복(409 "이미 가입된 이메일입니다.", DB UNIQUE가 최종), 로그인 실패(401 "이메일 또는 비밀번호를 확인해 주세요." — 이메일이 없는지 비밀번호가 틀렸는지 구분하지 않음), 가입 시 쿠폰 1장 발급, JWT 발급과 로그아웃 시 `revoked_tokens` 등록.

## 4. 조향 · 레시피 (`atelier/domain.py`)

| ID    | 규칙                                                                                                     | 위반 코드 → 메시지                                      |
| ----- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| AT-01 | 향료 구성(`counts`)은 `{향료 ID: 횟수}`. **있는 향료만**, 횟수는 0 이상의 정수                           | `COUNTS_INVALID` → 향 이름과 향료 조합을 확인해 주세요. |
| AT-02 | 횟수 **합계는 1~20**. 틀린 구성은 고치지 않고 거절한다(사용자의 비율을 바꾸지 않음). 0인 항목은 버린다   | `COUNTS_INVALID`                                        |
| AT-03 | 라벨은 `classic`·`paper`·`minimal`. 모르는 값은 `classic`으로 (화면과 같은 동작)                         | —                                                       |
| AT-04 | 비중 = 횟수 ÷ 합계. **저장하지 않고 계산**                                                               | —                                                       |
| AT-05 | 블렌딩 색 = 향료 색을 횟수로 가중 평균(채널별 반올림). **서버가 계산**하고 클라이언트 값은 쓰지 않음     | —                                                       |
| AT-06 | 레시피 이름은 공백 제외 1자 이상 30자 이하                                                               | `RECIPE_INVALID`                                        |
| AT-07 | 레시피는 **수정하지 않는다**. 다시 만들기 = 원본을 `parent`로 가리키는 새 레시피, 버전 = 원본 버전 + 1   | —                                                       |
| AT-08 | 초안은 방문자당 1개, 통째로 덮어쓴다. 구성은 AT-01·02, 이름 30자 이하, 단계는 `result`가 아니면 `select` | `DRAFT_INVALID` → 조향 초안을 확인해 주세요.            |

애플리케이션 계층에서 처리: 레시피 저장·삭제는 회원만(401 "로그인 후 향을 저장할 수 있어요."), 원본 레시피는 **본인 것**만(아니면 404 "저장한 원본 향을 찾을 수 없어요."), ID·생성 시각은 서버가 정함.

## 5. 주문 (`ordering/domain.py`)

장바구니는 브라우저에 있으므로 `POST /orders`가 `items`를 받는다. 서버는 **클라이언트가 보낸 가격·상품 정보·합계를 믿지 않고** 모든 항목을 카탈로그로 다시 만든다.

### 5.1 주문 항목 (`OrderItemInput`)

| ID    | 규칙                                                                                                                                         | 위반 코드 → 메시지                                            |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| OR-01 | 항목마다 `productId`와 `custom` 중 **정확히 하나**                                                                                           | `ITEM_INVALID` → 상품 또는 맞춤 조향 중 하나를 선택해 주세요. |
| OR-02 | `quantity`는 **1~15의 정수** (불리언·소수·문자열 불가)                                                                                       | `QUANTITY_INVALID` → 수량을 확인해 주세요.                    |
| OR-03 | 상품은 카탈로그에 있고 재고가 1 이상이어야 함                                                                                                | `PRODUCT_UNAVAILABLE` → 현재 선택할 수 없는 상품이에요.       |
| OR-04 | **Gift Set**: Gift Set과 같은 컬렉션, Gift Set이 아닌 단품, **서로 다른 3개**, 모두 재고 있음                                                | `GIFT_SET_INVALID` → 같은 컬렉션의 제품 3개를 선택해 주세요.  |
| OR-05 | 단가: 단품 = 상품 가격 / Gift Set = **고른 3개 가격의 합** / 맞춤 조향 = 오 드 퍼퓸 가격(카탈로그 첫 오 드 퍼퓸)                             | —                                                             |
| OR-06 | 단가를 알 수 없으면(가격 `null`이 하나라도 있으면) 주문 불가                                                                                 | `PRICE_UNKNOWN` → 주문 금액을 확인해 주세요.                  |
| OR-07 | 맞춤 조향: 오 드 퍼퓸만(`productType`이 있으면 `eau-de-parfum`), 이름 필수, 구성은 AT-01·02, 색은 서버가 재계산                              | `CUSTOM_TYPE_UNSUPPORTED` / `CUSTOM_INVALID`                  |
| OR-08 | 같은 항목은 합친다. 키: 상품 = `상품ID:선택한ID들(정렬)`, 맞춤 조향 = 이름·라벨·유형·구성의 해시. **합쳐서 15개를 넘으면 거절**(줄이지 않음) | `QUANTITY_INVALID`                                            |

### 5.2 주문 전체

| ID    | 규칙                                                                                                      | 위반 코드 → 메시지                              |
| ----- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| OR-09 | `items`는 1개 이상인 배열                                                                                 | `ITEMS_REQUIRED` → 주문할 상품을 확인해 주세요. |
| OR-10 | 재고: 단품과 **Gift Set 구성품을 합산**해 상품별 재고 이하 (Gift Set 상품 자체도 1개씩 계산, Mock과 동일) | `OUT_OF_STOCK` → 상품 재고를 확인해 주세요.     |
| OR-11 | 받는 분 1~100자, 주소 1~500자 (앞뒤 공백 제거)                                                            | `RECIPIENT_REQUIRED` / `ADDRESS_REQUIRED`       |
| OR-12 | 쿠폰 사용 요청은 사용 가능한 쿠폰이 있을 때만                                                             | `COUPON_UNAVAILABLE`                            |
| OR-13 | 배송비: 상품 합계 **50,000원 이상 무료**, 아니면 **3,000원**. 쿠폰 사용 시 무료                           | —                                               |
| OR-14 | 총액 = 상품 합계 + 배송비. 주문 응답의 각 항목에 서버가 계산한 `unitPrice` 포함                           | —                                               |
| OR-15 | 거절된 주문은 아무것도 바꾸지 않는다 (주문·재고·쿠폰 모두 그대로)                                         | 애플리케이션 계층의 트랜잭션 롤백               |

도메인의 재고 검사(OR-10)는 카탈로그 스냅샷 기준의 **사전 검사**다. 동시에 들어온 주문의 최종 판단은 애플리케이션 계층의 **조건부 재고 차감**(`재고 ≥ 필요 수량`일 때만 차감)과 DB `CHECK(stock ≥ 0)`이 한다. 도메인은 차감할 수량(`stock_needs`)을 계산해 넘긴다.

## 6. 입점 문의 (`partner/domain.py`)

| ID    | 규칙                                                                                                 | 위반 코드 → 메시지                                         |
| ----- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| PT-01 | 필수: 브랜드(100자)·담당자(50자)·이메일(254자)·소개(3,000자)·문의 내용(3,000자)·유형. 앞뒤 공백 제거 | `INQUIRY_INVALID` → 필수 입력 항목을 확인해 주세요.        |
| PT-02 | 이메일 형식, 개인정보 동의는 폼 값 `"on"`이어야 함                                                   | `INQUIRY_CONSENT` → 필수 입력 항목과 동의를 확인해 주세요. |
| PT-03 | 유형은 `향수` · `바디 · 헤어` · `홈 프래그런스` · `기타 향 제품` 중 하나                             | `INQUIRY_INVALID`                                          |
| PT-04 | 웹사이트는 선택, 255자 이하. 비어 있으면 저장하지 않음                                               | `INQUIRY_INVALID`                                          |

글자 수 제한은 ERD 컬럼 크기를 따른다. 화면 입력 제한(`maxLength`)과 같거나 더 넉넉하다.

## 7. 코드 구조

```text
apps/api/aura_api/domain/
  errors.py              # DomainError와 kind
  catalog.py             # Product, Ingredient, Catalog (규칙이 참고하는 상품·향료 사실)
  identity.py            # 가입·로그인 입력, RequestOwner, Coupon
  atelier.py             # 향료 구성, 블렌딩 색, 레시피·초안
  ordering.py            # 주문 항목 재구성, Gift Set, 재고 수요, 금액·배송비
  partner.py             # 입점 문의 입력
apps/api/tests/domain/   # 규칙별 단위 테스트 (DB 없음)
```

다른 계층은 계층별 폴더에 영역 이름으로 둔다: 표현 `aura_api/api/`, 서비스 `aura_api/services/`, 인프라 `aura_api/infra/`(DB·ORM 모델·저장소). 도메인 계층만 다른 계층을 import하지 않는다.

## 8. 결정 · 확인 필요

| 항목                    | 이 문서의 기본값                                                                                                      | 상태                              |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 세션 방식               | JWT (세션 쿠키 값), 로그아웃 시 `revoked_tokens`                                                                      | **결정**                          |
| 주문 생성 방식          | `POST /orders`가 `items`를 받음                                                                                       | **결정** (BFF 계약 #24)           |
| 맞춤 조향 주문          | 허용, 단가 = 오 드 퍼퓸 가격 (Mock과 동일). `allow_custom=False`로 끌 수 있음                                         | 확인 필요                         |
| 재고 차감               | 주문 시 차감. 단품 + Gift Set 구성품 + Gift Set 상품                                                                  | 확인 필요                         |
| 쿠폰 복원               | 주문 취소 시 복원                                                                                                     | 확인 필요 (취소 기능 범위와 함께) |
| 도메인 오류 메시지 노출 | 현재 공통 오류 처리기는 상태 코드별 공통 문구만 내보낸다. 도메인 `message`를 BFF `detail`로 전달할지 공통 모듈과 합의 | 확인 필요                         |

## 9. 테스트 실행

```sh
npm run check:api
```

`apps/api/tests/domain/`의 테스트는 규칙마다 **맞는 경우와 틀린 경우**를 확인한다. DB와 서버 없이 실행된다.
