## 3. 기능 요구사항

**우선순위:** P0 = 핵심 화면 흐름에 꼭 필요 / P1 = 연결 완성도 / P2 = 여유가 있을 때. 경로는 BFF 공개 경로이며 FastAPI에서는 `/api`가 `API_PREFIX`(`/api/v1`)로 바뀐다.

### 3.1 상품 (CAT)

| ID        | 우선 | 경로                             | 요구사항 · 인수 기준                                                                                 |
| --------- | ---- | -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| FR-CAT-01 | P0   | `GET /api/catalog`               | `Catalog`(상품 30·컬렉션 3·유형 10·향료 24·향 계열·추천 이름·홈 콘텐츠) 반환. Mock과 같은 값·원본 ID |
| FR-CAT-02 | P0   | `GET /api/catalog/products/{id}` | 상품 1개 반환, 없는 ID는 404. 기존 별칭 ID(`bergamot-veil` 등)도 Mock과 같이 처리                    |
| FR-CAT-03 | P0   | —                                | 가격이 정해지지 않은 상품은 `price: null`. 임의 가격을 만들지 않음                                   |
| FR-CAT-04 | P1   | —                                | 상품 재고를 제공하고 주문 시 서버 재고로 판단                                                        |

### 3.2 회원 · 인증 (AUTH)

| ID         | 우선 | 경로                                | 요구사항 · 인수 기준                                                                                                                    |
| ---------- | ---- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| FR-AUTH-01 | P0   | `GET /api/auth/me`                  | `AccountState { user: Member \| null, guestId }` 반환. 처음 온 방문자에게는 비인증 `guestId`만 발급; JWT는 회원 인증에만 사용           |
| FR-AUTH-02 | P0   | `POST /api/auth/register`           | `{ name, email, password, marketing? }` → 201 `AccountState`. 가입과 동시에 로그인. 같은 이메일은 409                                   |
| FR-AUTH-03 | P1   | (가입 시)                           | 신규 회원 배송비 쿠폰 1장 발급, 중복 발급 없음. `Member.coupon`으로 보유 여부 표시                                                      |
| FR-AUTH-04 | P0   | `POST /api/auth/login`              | `{ email, password }` → `AccountState`. 실패는 401 "이메일 또는 비밀번호를 확인해 주세요." (어느 쪽인지 숨김)                           |
| FR-AUTH-05 | P0   | `POST /api/auth/logout`             | 본문 없음 → `AccountState`(user: null, **같은 guestId**). Access Token `jti` 폐기 + Refresh Token 계열 폐기                             |
| FR-AUTH-06 | P0   | (모든 회원 경로)                    | 새로고침·새 탭에서도 로그인 유지. 만료·위조·폐기된 토큰은 401(`WWW-Authenticate: Bearer`)                                               |
| FR-AUTH-07 | P1   | (회원 변경 요청)                    | `X-Account-Owner`가 실제 주인과 다르면 409. 소유권은 이 헤더가 아니라 토큰으로 판단                                                     |
| FR-AUTH-08 | P0   | (로그인·가입 시)                    | Refresh Token 발급. DB에는 **해시만** 저장하고 만료·사용·폐기 상태를 관리                                                               |
| FR-AUTH-09 | P0   | `POST /api/auth/refresh`            | 유효한 Refresh Token으로 새 Access Token 발급. 쓰인 Refresh Token은 새것으로 **회전**                                                   |
| FR-AUTH-10 | P0   | (재발급 시)                         | 이미 쓰인 Refresh Token이 다시 오면 탈취로 보고 **같은 계열 전체 폐기**                                                                 |
| FR-AUTH-11 | P2   | (로그인·요청 시)                    | `users.is_active = false`인 회원의 로그인·보호 요청·Refresh를 거절                                                                      |
| FR-AUTH-12 | P1   | `POST /api/v1/auth/change-password` | 현재 비밀번호 확인 후 새 비밀번호로 변경하고 모든 Access·Refresh를 폐기. 성공은 204, 현재 BFF·화면 연결은 후속                          |
| FR-AUTH-13 | P1   | `DELETE /api/v1/auth/me`            | 현재 비밀번호 확인 후 계정을 비활성화하고 마케팅 동의·가용 쿠폰·개인 레시피를 정리하며 모든 토큰 폐기. 성공은 204, BFF·화면 연결은 후속 |

Refresh Token 회전은 백엔드가 수행하고 BFF가 HttpOnly 쿠키로 보관한다. 브라우저는 Web Lock으로 갱신을 직렬화하고 Access 만료 시 자동 갱신 후 한 번 재시도한다. Refresh도 거절되면 두 인증 쿠키를 지우고 다시 로그인한다.

## 4. 업무 규칙

업무 규칙의 전체 목록·위반 코드·메시지는 [도메인 규칙](DOMAIN_RULES.md)에 있다. 요약:

| 영역     | 핵심 규칙                                                                                                          | 도메인 규칙 ID |
| -------- | ------------------------------------------------------------------------------------------------------------------ | -------------- |
| 회원     | 이메일 소문자 정규화·중복 금지, 비밀번호 8~256자, 배송비 쿠폰 1회 사용                                             | ID-01~09       |
| 조향     | 있는 향료만, 투입 합계 1~20, 라벨 3종, 레시피는 수정하지 않고 새 버전, 색·비중은 서버 계산                         | AT-01~08       |
| 주문     | 수량 1~15, Gift Set 같은 컬렉션 서로 다른 3개, 가격 미정 주문 불가, 단품+구성품 합산 재고, 5만 원 이상 배송비 무료 | OR-01~15       |
| 입점문의 | 필수 항목·글자 수·이메일 형식·동의(`"on"`)·유형 4종, 이메일별 10분 3건 제한                                        | PT-01~05       |
| 관리자   | 낙관적 잠금(`version`), 재고 0~99,999, 재고 조정 사유 필수, 변경은 감사 기록                                       | 추가 예정      |

## 8. 현재 정책과 후속 확인

| 항목                         | 현재 기본값                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 비회원 주문                  | 현재 FastAPI는 회원만 허용하고 비회원은 401. 정책 변경 시 ERD·API·BFF를 함께 변경                            |
| 맞춤 조향 주문               | 허용, 단가 = 오 드 퍼퓸 가격 (Mock과 동일)                                                                   |
| 재고 차감 대상               | 단품 + Gift Set 구성품 + Gift Set 상품 (Mock 재고 검사와 동일)                                               |
| 쿠폰 유효기간·취소 시 복원   | 유효기간 없음, 취소 기능은 범위 밖                                                                           |
| 도메인 오류 메시지 노출      | 서버가 고정한 `code`·`message`를 공통 오류 형식으로 반환하고 BFF가 4xx와 메시지를 보존                       |
| 주문 멱등성                  | 선택적 `Idempotency-Key`를 FastAPI와 BFF가 지원. BFF는 키를 만들거나 쓰기를 재시도하지 않음                  |
| Refresh Token 테이블·컬럼    | 마이그레이션 0002의 `auth_token_families`·`refresh_tokens`와 `family_id` 계열로 구현                         |
| Refresh 재발급 경로·수명     | `/auth/refresh`; Access 기본 15분, Refresh 기본 7일. 관리자는 Refresh 없이 Access 기본 1시간                 |
| 회원 정지(`users.is_active`) | 컬럼·검증은 구현됨. 회원을 정지·복구하는 관리자 운영 기능은 후속 범위                                        |
| 관리자 인증 BFF 계약         | 별도 `admins`·관리자 JWT·`aura_admin_access` 쿠키로 구현. 회원 인증·캐시와 분리                              |
| 회원 계정 비활성화           | `users` 행·이메일·주문은 유지하고 가용 쿠폰·개인 레시피만 정리. 완전 파기·재가입·복구 정책과 BFF 화면은 후속 |
