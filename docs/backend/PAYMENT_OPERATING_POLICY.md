# 결제·주문 운영 정책 반영

이번 변경은 API의 경로나 응답 필드를 추가하지 않습니다. 기존 결제·환불과 미결제 만료 CLI를 재사용합니다.
실제 환경변수를 변경하거나 운영 스케줄러를 등록·실행하지 않았습니다.

## 확정 정책 4가지

1. 미결제 주문은 생성 후 10분부터 만료 대상입니다. 설정 예시는
   `AURA_UNPAID_ORDER_TTL_MINUTES=10`이며 기본값도 10입니다. CLI는 기본 dry run입니다.
   `IN_PROGRESS`와 `DONE` 결제는 후보 한도 적용 전에 제외하며, 취소 직전 주문 잠금과 상태·결제
   재검사를 유지합니다. 9분 59초는 유지하고 10분·10분 1초는 취소 대상인 것을 검증합니다.
2. 환불이 확정된 뒤에만 사용 쿠폰을 반환합니다. 주문 취소·재고·쿠폰·이력·환불 완료 기록을 같은
   트랜잭션으로 반영합니다. 실패·결과 불명에서는 반환하지 않으며 반복 취소로 추가 복구하지 않습니다.
3. `received`는 기존 미결제 취소, `paid`·`preparing`은 전액 환불 뒤 취소입니다.
   `shipped`·`delivered`는 거절합니다. 환불 예약과 배송 상태 변경은 같은 주문 행 잠금으로 직렬화합니다.
   배송이 먼저 확정되면 환불을 요청하지 않고, 환불이 먼저 예약되면 `REFUND_IN_PROGRESS`로 배송을 막습니다.
   PG 호출은 트랜잭션 밖에서 수행합니다. 부분 환불·배송 후 반품은 구현하지 않습니다.
4. 관리자 대시보드의 매출 합계에서 `cancelled`만 제외합니다. 주문 건수와 기간 조건은 유지합니다.
   환불 확인 중인 `paid`·`preparing` 주문은 완료 전까지 합계에 남습니다. 그 외 상태의 매출 산식은
   이번 작업에서 바꾸지 않습니다.

## 검증 및 협업 경계

- `test_operating_policy.py`: 10분 경계, dry run/실행 일치, 환불 진행·확정에 따른 매출과 주문 건수.
- `test_refunds.py`: 준비 중 환불·쿠폰 1회 복구와 배송 경쟁. 기존 PG 성공 후 DB 오류·재시도·
  동시 환불·쿠폰 및 재고 테스트를 재사용합니다.
- `test_order_cancellation.py`: 기존 승인·취소 경쟁, 미결제 만료와 재실행 안전성 유지.
- 만료·승인 동시 실행 4회와 준비 중 환불의 PG 호출 중 `NOWAIT` 잠금 검사를 포함합니다.
  CLI 단위 테스트 4개는 실제 DB 호출을 대체하고 기본 dry run·명시적 실행·잘못된 TTL 거절을 검사합니다.
- 이번 검증은 일회용 PostgreSQL 18과 모의 PG를 사용합니다. 실제 토스 API를 새로 호출하지 않습니다.
- PR #82의 관리자 조회 API·계약 1.5.0은 별도 임시 작업 트리에서 함께 검사합니다.
  이 브랜치에는 PR #82를 병합하거나 해당 구현을 복사하지 않습니다.
- 운영 담당자는 향후 스케줄 주기·알림·미해결 건 처리 절차를 정해야 합니다. PG 불명 건을 임의로
  실패 처리하거나 만료 취소해서는 안 됩니다. BFF 취소 화면과 202 재확인 안내는 별도 담당 작업입니다.
