# 회원 탈퇴: 복구 없는 비활성화와 같은 이메일 재가입 (마이그레이션 0010)

CRA-34·36 보완입니다. 30일 유예·로그인 복구([유예 문서](MEMBER_DELETION_GRACE.md))를 **대체**합니다. 이전
정책에서 바뀐 부분이라 배포 전에 팀 확인이 필요합니다.

## 정책 (코드에 적용됨)

| 항목                    | 동작                                                                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 탈퇴(`DELETE /auth/me`) | 비밀번호 확인 뒤 `is_active=false`, `marketing=false`, `deactivated_at` 기록, 비밀번호 해시를 `!deleted`로 교체, 모든 Access/Refresh 폐기. 한 트랜잭션 |
| 로그인                  | 탈퇴한 계정은 올바른 비밀번호로도 401. 복구 경로 없음(`restore_token_family`는 항상 거절)                                                              |
| 같은 이메일 재가입      | 허용. 새 회원 ID로 생성되고 이전 계정의 주문·쿠폰·레시피와 자동으로 연결되지 않음                                                                      |
| 이메일 유일성           | `users_email_lower_key`가 `deactivated_at IS NULL`인 행에만 적용(부분 유니크). 정지(`is_active=false`, 탈퇴 아님) 계정은 이메일을 계속 점유            |
| 주문·결제·환불          | 삭제·수정하지 않음. 탈퇴 전후 행이 동일함을 테스트로 확인                                                                                              |
| 관리자 화면             | 탈퇴한 회원의 이름·이메일을 주문·결제·환불 검토 목록에 보여주지 않음(`customer: null`)                                                                 |
| 자동 삭제(purge)        | **새 탈퇴는 예약되지 않음.** `purge_members`는 `deactivated_at`이 있는 계정을 처리하지 않음                                                            |

## 마이그레이션 0010

- `users.deactivated_at` 추가, CHECK(`deactivated_at IS NULL OR NOT is_active`).
- 0005의 `deletion_requested_at`이 있던 비활성 계정은 `deactivated_at`을 받아 **복구·자동 삭제 대상에서 빠짐**.
- 이메일 유니크 인덱스를 부분 인덱스로 교체.
- 되돌리기: 탈퇴한 회원이 한 명이라도 있으면 **거절**(재사용된 이메일을 삭제·개명으로 풀지 않음). 검토된 절차가
  필요합니다.

## 웹 장바구니 (서버에 저장하지 않음)

- 저장 키를 소유자별로 분리: `aura_cart_v2:guest`, `aura_cart_v2:member:<회원 ID>`. 회원은 비회원 장바구니를
  가져오지 않고, 로그아웃하면 비회원 장바구니가 그대로 보입니다. 기존 `aura_cart_v1`은 읽지도 지우지도 않습니다.
- 탈퇴 API가 정확히 **204**를 돌려준 뒤에만 해당 회원의 키를 지우고 "폐기" 표시를 남깁니다. 비회원·다른 회원·옛 키는
  유지하고, 다른 탭의 늦은 쓰기가 폐기된 장바구니를 되살리지 못합니다.
- 장바구니 변경은 로그인·탈퇴와 같은 탭 간 잠금 안에서 `/api/auth/me`로 소유자를 다시 확인한 뒤 씁니다.
- 한 탭의 탈퇴·로그인·로그아웃은 다른 탭에 알려 계정 캐시를 다시 확인하게 합니다.
