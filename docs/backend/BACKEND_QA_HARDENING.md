# 결제·주문 QA 후속 보완

## 재현과 수정

- PG 인증 오류, 조회 실패, 요청 제한과 알 수 없는 오류는 결제 실패의 증거가 아닙니다.
  `IN_PROGRESS`를 유지하고 같은 결제/환불 ID의 멱등 키로 재확인합니다.
  명시적으로 허용한 결제 거절 코드만 `FAILED`로 닫습니다. 조회 HTTP 오류는 항상 결과 불명입니다.
  `NOT_FOUND_PAYMENT_SESSION`도 이전 승인 여부를 확정하지 않으므로 보류합니다.
- HTTP 200이라도 JSON 객체와 문자열 `status`가 아니면 결과 불명입니다.
  잘못된 JSON, `null`, 배열, 숫자, 잘못된 상태 자료형이 내부 오류로 새지 않도록 검사합니다.
- PG 원문 오류 메시지는 저장·공개하지 않고 고정 공개 메시지로 바꿉니다.
  실제 비밀키를 테스트에 사용하지 않았고 새 로깅도 추가하지 않았습니다.
- 미결제 만료 후보는 `LIMIT` 전에 `IN_PROGRESS`·`DONE` 결제를 제외합니다.
  선택 후에도 주문 잠금과 상태·결제 재확인을 유지합니다. `due`는 보류 건을 제외한 후보 수이며,
  실행 직전 상태가 바뀐 건만 `skipped`에 포함될 수 있습니다.
- 맞춤 주문 이름의 UTF-8 인코딩 불가능 문자는 기존 `CUSTOM_INVALID` 400으로 거절합니다.
  정상 한국어·이모지는 유지하며 입력 원문은 오류 메시지에 넣지 않습니다.
- 결제 재확인의 개별 조회·기록 DB 오류는 롤백하고 해당 건을 보류로 집계합니다.
  다음 결제는 계속 처리하며, 실패 건은 기존 멱등 키로 다음 실행에서 재시도합니다.
  후보 목록 자체를 읽지 못한 경우에는 배치 실패를 그대로 알립니다.

## 검증 환경과 경계

수정 전 PG 관련 34개, Unicode 이름 2개, 만료 정체 및 재확인 기록 실패 각 1개의
실패를 재현했습니다. 단위 테스트와 실제 PostgreSQL 회귀 테스트를 함께 사용합니다.
DB 테스트는 이 작업만을 위해 새로 초기화한 PostgreSQL 18의 `127.0.0.1:55439`
일회용 클러스터에서만 수행합니다. 기존 개발·운영 DB와 실제 PG는 사용하지 않습니다.

PR #82는 별도 분리 작업 트리에서 호환성을 검증하며 원본 브랜치를 병합하거나 수정하지 않습니다.
인증 장애를 보류로 바꾼 결제·환불은 기존 시간 기준을 지난 뒤 관리자 검토 목록에 포함되어야 합니다.
관리자 조회 API를 이 작업에서 다시 구현하지 않습니다.

전체 실행 결과 및 기존 실패 여부는 PR 본문에 기록합니다. PG의 실제 응답과 네트워크를 사용하는
결제 검증은 이번 모의 PG 테스트로 보장하지 않습니다.
