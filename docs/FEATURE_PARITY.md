# 기능 연결 점검·보완

대상: 운영 FastAPI/PostgreSQL, Next.js BFF와 사용자·관리자 화면. 실제 운영 비밀번호와 결제 키는 이 문서에 기록하지 않습니다.

| 흐름           | 확인한 문제                                      | 보완                                                                                                           |
| -------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 상품 Q&A       | 안내 문구만 있고 작성·저장·관리자 답변 경로 없음 | 상품별 목록·작성, 내 문의, 수정·삭제, 관리자 미답변 필터·답변·답변 수정                                        |
| 문의 개인정보  | 상품 문의 정책·권한 없음                         | 기본 비공개, 작성자·관리자에게만 제목·본문·답변 제공, 타인의 변경은 404, 버전 충돌 409, 회원별 10분/5건 제한   |
| 주문 접수      | 배송 입력 일부가 저장되지 않고 결제 버튼 비활성  | 받는 분·연락처·주소·요청사항 저장, 서버 가격·재고 검증, Idempotency-Key 재시도, 서버 확정 금액으로 테스트 결제 |
| 결제 이후      | 주문 상태·취소 UI 없음                           | 내 주문 상태·운송장, 미결제 이어하기·취소, 결제 완료/준비 중 전액 환불 요청, 결과 미확정 안내                  |
| 관리자 주문    | 조회만 가능                                      | 결제 완료→준비→배송→완료, 배송 시 택배사·운송장 필수, 이전 상태 비교·행 잠금·처리 이력, 환불 진행 중 변경 차단 |
| 결제·환불 검토 | API만 있고 관리자 화면 없음                      | 검토 목록·페이지 이동·새로고침, PG 비밀 식별자는 BFF 응답에서 제외                                             |
| 자동 처리      | 만료·재확인 CLI만 있고 스케줄 없음               | 매분 미확정 PG 재확인 후 미결제 만료, 실행마다 현재 DB URL 파일 읽기                                           |
| 관리자 계정    | 최초 계정이 없고 비밀번호 변경 없음              | 명시적 요청에 따라 운영 임시 관리자 생성, 본인 비밀번호 변경 시 모든 관리자 세션 폐기, 로그인과 변경 직렬화    |
| 저장한 향      | 삭제 UI 없음, 구매 필터가 항상 빈 화면           | 기존 삭제 API 연결, 결제 완료 이후 주문의 커스텀 향 스냅샷으로 구매 내역 표시                                  |
| 입점 문의      | 실제 저장 후에도 Mock 문구 표시                  | 실제 접수·관리자 확인 문구로 수정                                                                              |
| CI             | 실 DB 테스트가 기본적으로 건너뛰어짐             | 전용 PostgreSQL 테스트와 PC·모바일 주문/문의 브라우저 흐름 추가                                                |

## 경계와 남은 제품 범위

현재 토스는 테스트 키만 허용합니다. 실제 청구·택배사 연동·메일 발송·제조 공정 검증을 완료했다고 간주하지 않습니다. 상품 전성분·사업자 정보·교환/반품의 확정 운영 자료는 실제 자료가 필요하며 임의로 작성하지 않습니다.

기존 상품·재고 수정 및 입점 문의 상태/메모 관리는 실제 API에 연결되어 있습니다. 상품 신규 등록·판매 노출/중지·이미지 업로드·상품 상세/배송/교환 안내 편집을 관리자 화면에 연결했습니다. 같은 컬렉션·유형에 다른 용량이나 구성을 추가할 수 있고, 기존 주문 스냅샷은 유지됩니다. 컬렉션·향료 자체의 신규 등록은 현재 고정 카탈로그 범위 밖입니다. 리뷰·찜·주소록·쿠폰 발급 캠페인은 기존 화면의 연결 누락과 별개인 신규 제품 기능입니다. PRD에서 제외한 포인트·회원 카드·픽업은 추가하지 않았습니다.

## 검증

- 일회용 PostgreSQL에서 전체 API 테스트, 문의 비공개·소유권·버전 충돌, 배송 정보 보존과 중복 접수 방지, 배송 상태 동시 변경, 관리자 세션 폐기를 확인합니다.
- `playwright.commerce.config.ts`는 실제 FastAPI·PostgreSQL·BFF·화면을 사용합니다. 외부 토스 SDK와 PG 응답만 테스트 전용으로 대체하며 운영 이미지에 테스트 PG를 넣지 않습니다.
- PC·모바일에서 문의 작성→관리자 답변→본인 삭제와 주문 응답 유실→동일 키 재시도→결제→장바구니 정리→전액 환불을 검증합니다.
- 운영 검증은 공개 페이지와 로그인 후 읽기 경로, 마이그레이션·타이머·복제 상태를 확인합니다. 기능 검증은 격리 DB에서 수행합니다. 별도로 요청된 운영 데이터 적재는 일반 회원·조향·문의·주문 서비스로 처리합니다.
